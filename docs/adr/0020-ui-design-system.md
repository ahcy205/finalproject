# 0020. 화면 디자인을 "생활관 안내판" 기준으로 다시 만든다

- 상태: 채택
- 날짜: 2026-10-31

## 배경

화면 30개가 무료 HTML 템플릿(FreeHTML5) 위에 만들어져 있고, 스타일을 입히는 방식이 화면마다 달랐다.

- **Bootstrap 버전이 섞여 있다.** 테마의 Bootstrap 3, 일부 화면의 Bootstrap 5 CDN, `base.html`의 또 다른 Bootstrap이 함께 쓰인다. Bootstrap 5 클래스(`d-flex`, `text-end` 등)는 Bootstrap 3만 불러온 화면에서 아무 효과가 없다.
- **jQuery 플러그인 12개를 모든 화면에서 불러온다.** 그중 3개는 어디에서도 쓰지 않고, 카운트다운 데모 코드가 9개 화면에 남아 있다.
- **글꼴과 색이 화면마다 다르다.** 글꼴은 4종이 섞여 있고, 분홍 배경과 Bootstrap 기본 파랑이 섞여 있다.
- **사용성 문제가 있다.**
  - 모바일에서 메뉴를 열 수 없다.
  - 10개 화면에는 메뉴가 아예 없다.
  - 오류와 성공을 브라우저 `alert()` 창으로 알린다.

## 결정

1. **디자인 방향은 "생활관 안내판"으로 한다.** 학생이 하루에도 여러 번 휴대폰으로 확인하는 서비스이므로, 홍보 화면이 아니라 건물 안내판과 관리실 창구처럼 만든다.
   - **색**:

     | 이름 | 값 | 쓰임 |
     |---|---|---|
     | 바탕 | `#F4F6F5` | 화면 배경 |
     | 글자 | `#1B2420` | 본문 글자 |
     | 안내판 녹색 | `#1F5E4B` | 주색 |
     | 황동 | `#B8862B` | 지금·오늘 표시에만 |
     | 경고 | `#B3261E` | 오류·위험 |
     | 선 | `#D6DDD9` | 구분선 |

   - **글꼴**: Pretendard 하나만 쓴다. 시각과 호실은 숫자 폭이 같은 숫자로 보여 준다.
   - **강조 요소**: 눈에 띄는 요소는 "호실 번호판" 모양의 시각·숫자 표시 하나로 한다. 나머지는 줄로 구분한 목록과 표로 차분하게 둔다. 모든 내용을 같은 둥근 카드에 넣거나, 그라데이션 장식이나 스크롤 애니메이션을 쓰지 않는다.
   - **움직임**: 메뉴 열기, 알림처럼 사용자 동작에 반응할 때만 쓰고, 동작 줄이기 설정을 지킨다.
2. **예전 테마, Bootstrap 3·5, jQuery 플러그인은 걷어내고 직접 만든 CSS로 바꾼다.** 새 라이브러리는 추가하지 않는다.
3. **화면을 한꺼번에 바꾸지 않고 PR 9개로 나눈다.** 중간에도 모든 화면이 동작하도록, 공통 틀의 CSS는 `.dg-` 클래스로만 선택해 예전 테마 화면에도 함께 들어갈 수 있게 한다.
   - 공통 틀: `static/css/dorm-shell.css`, `static/js/dorm-shell.js`, `templates/web/_shell_head.html`
   - 순서: 1 공통 틀 → 2 홈 → 3 입실·외박 신청 → 4 마이페이지 → 5 게시판·공지 → 6 안내 화면 → 7 챗봇 → 8 로그인·회원가입 → 9 관리자 화면
   - 마지막 화면을 옮기면 예전 테마 파일을 지운다.

### 1단계 (이번 PR): 공통 틀

- **상단 메뉴** (`_nav.html`, ADR 0004의 공통 템플릿 유지)
  - 묶음: 생활·안내·커뮤니티·관리(직원)·마이페이지. 식단표·셔틀버스·주변 편의시설도 메뉴에 넣었다.
  - 넓은 화면에서는 묶음별 펼침 메뉴를 쓴다. 마우스를 올리거나, 클릭하거나, 키보드로 열 수 있고 Esc로 닫는다.
  - 960px 미만에서는 오른쪽 서랍으로 연다.
  - 강조할 묶음은 화면 이름으로 정한다(`web.context_processors.nav`). 지금 보고 있는 화면 링크에는 `aria-current="page"`를 단다.
- **메뉴를 모든 화면에 넣었다.** 메뉴가 없던 화면: 로그인, 회원가입, 마이페이지, 신청 완료, 입실 신청 관리, 외박 신청 관리, 문의 상세, 상벌점, 삭제 확인 2개
- **Django 메시지는 공통 알림(`_messages.html`)으로 보여 준다.**
  - `alert()` 창으로 띄우던 화면 4곳과 본문에 따로 찍던 화면 3곳을 정리했다.
  - 성공과 안내는 6초 뒤 사라지고, 오류와 경고는 닫을 때까지 남는다.
- 예전 테마(`main.js`)가 만드는 모바일 메뉴 버튼은 새 메뉴와 겹치므로 숨긴다.

## 감수하는 점

- 화면을 모두 옮길 때까지 메뉴는 새 디자인, 본문은 예전 디자인인 상태가 잠시 이어진다.
- 예전 테마의 구조(CSS 불러오는 순서, `fh5co-nav` 클래스)를 고정한 테스트는 새 구조에 맞게 바꾼다. 오류 문구, 권한, 쿼리 수 테스트는 그대로 둔다.
- Pretendard는 CDN(jsDelivr)으로 불러온다. 다른 CDN(Google Fonts, Bootstrap)도 이미 쓰고 있고, 로컬 실행 전용 서비스라(ADR 0002) 직접 넣지 않았다.

## 확인 방법

- `tools/snapshot.py` 화면 비교로 바뀐 화면이 의도한 화면인지 확인한다.
- Chrome으로 휴대폰(390px), 태블릿(768px), PC(1280px) 화면을 캡처해 확인한다.

## 진행 결과 (2026-10-31)

PR #66–#75로 화면 30개를 모두 옮겼고, #76에서 예전 테마 파일을 지웠다: `templates/base.html`, `_theme_css.html`, `_theme_js.html`, `static/` 아래 테마 CSS·JS·글꼴·이미지·Sass(Bootstrap 3·5, jQuery와 플러그인 12개 포함). 남은 정적 파일은 `css/dorm-shell.css`, `css/dorm.css`, `js/dorm-shell.js`, `js/dorm-map.js` 네 개다.
