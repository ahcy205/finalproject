# 0013. 챗봇 콜드 스타트는 모델 유지 시간과 미리 깨우기로 줄인다

- 상태: 채택
- 날짜: 2026-10-28

## 배경

학생 챗봇을 직접 써 보니 답이 너무 오래 걸렸다. 한 번의 답을 단계별로 재 보니, 답을 만드는 시간보다 **모델을 처음 올리는 시간(콜드 스타트)**이 컸다.

| 단계 | 시간 |
|---|---|
| 질문 임베딩 | 0.05초 |
| 근거 검색 | 0.1초 |
| LLM 문장 생성 (모델이 올라와 있을 때) | 3~4초 |
| 서버 시작 후 첫 질문: 임베딩 모델(bge-m3) 로딩 | +7.3초 |
| Ollama가 모델을 내린 뒤: LLM 로딩 | +2.4초 |
| 모델을 올린 뒤 첫 생성: 긴 지시문(규칙·예시)을 처음 읽음 | +4초 안팎 |

Ollama는 기본적으로 마지막 요청 뒤 5분이 지나면 GPU 메모리를 비우려고 모델을 내린다. 그래서 잠깐 쉬었다 물을 때마다 콜드 스타트가 다시 생겼다.

## 결정

1. **모델 유지 시간 30분** (`keep_alive`): 요청마다 Ollama에 "마지막 요청 뒤 30분 동안 내리지 말 것"을 보낸다.
   - 30분은 마지막 질문부터 센다. 이용자가 계속 있으면 모델은 내려가지 않는다.
   - 설정: 환경변수 `KNOWLEDGE_LLM_KEEP_ALIVE` (`30m`, `2h`, `-1`=계속 유지).
   - 30분으로 정한 이유: 개인 노트북이라 GPU(8GB)를 다른 작업에도 쓴다. 챗봇 전용 서버라면 `-1`이 맞다.
2. **챗봇 화면을 열 때 미리 깨우기** (`knowledge.chat.start_warm_up`): 화면을 여는 순간 뒤에서 두 모델을 올린다. 학생이 질문을 입력하는 동안 준비가 끝난다.
   - 임베딩 모델(CPU, Django 프로세스)과 LLM(GPU, Ollama)을 **동시에** 올린다. 차례로 올리면 두 시간의 합만큼 걸려, 8초 안에 끝나지 않았다(첫 답 8.0초).
   - LLM은 실제 질문과 **같은 옵션**(`num_ctx` 등)으로 올린다. 처음에는 옵션 없이 올렸는데, 옵션이 다르면 Ollama가 질문 때 모델을 다시 올려서 첫 답이 6.3초였다.
   - 같은 **지시문을 한 번 읽혀 둔다**(답은 1토큰만 생성). Ollama는 앞부분이 같은 프롬프트를 재사용하므로, 첫 질문도 지시문을 다시 읽지 않는다.
   - 5분 안에 이미 깨웠으면 다시 하지 않는다. 실패하면 경고 로그만 남기고, 질문할 때 다시 시도된다.
   - 임베딩 모델 로딩에 잠금을 둬서, 미리 깨우기와 첫 질문이 동시에 와도 모델(약 2.2GB)을 한 번만 올린다.

## 측정

모델을 모두 내린 상태(`ollama stop`, 새 프로세스)에서 "기숙사 통금 몇 시까지야?"를 물었다. 미리 깨우기는 화면을 열고 8초 뒤(질문 입력 시간) 묻는 경우다. 두 번씩 쟀다.

| 방식 | 첫 질문 | 두 번째 질문 |
|---|---|---|
| 미리 깨우기 없음 | 13.0초 / 12.6초 | 3.3초 / 2.8초 |
| 차례로 깨우기, 옵션 없이 (시도) | 8.0초 | 3.8초 |
| 동시에 깨우기, 옵션 없이 (시도) | 6.3초 | 2.6초 |
| **동시에, 같은 옵션, 지시문까지 읽혀 둠 (채택)** | **3.2초 / 3.5초** | 3.0초 / 3.5초 |

## 검토한 다른 안

- **GPU 스냅샷:** 서버를 0대로 줄였다가 요청이 오면 켜는 서버리스 GPU(Modal 등)에서, 모델이 올라간 상태를 저장했다 복원하는 기술이다. 서버를 끄지 않는 로컬 PC에서는 모델을 내리지 않는 것(유지 시간)이 같은 효과를 더 단순하게 낸다. Ollama에는 이 기능이 없고, 비슷한 도구(cuda-checkpoint)는 Linux 전용이다.
- **답을 한 글자씩 흘려 보여 주기(스트리밍):** 체감 시간은 가장 짧아지지만, 이 챗봇은 답을 다 쓴 뒤 인용을 검사해 통과하지 못하면 숨긴다(ADR 0011). 흘려 보여 준 답을 나중에 거둘 수는 없다.
- **답을 짧게, 더 빠른 모델:** 예전 측정에서 답을 짧게 하라고 하자 사실 오류가 늘었고(ADR 0011), gemma4:e2b는 0.8초지만 사실 정확도가 낮다(ADR 0008). 콜드 스타트를 없앤 뒤의 3~4초가 길다고 판단되면 다시 측정한다.

## 한계

- 미리 깨우기는 웹 챗봇 화면에서만 한다. 앱(API)은 유지 시간 30분에만 기댄다.
- Ollama는 기본 설정에서 질문을 한 번에 하나씩 처리한다. 동시 이용자가 많으면 기다리는 시간이 길어진다(동시 처리 수, 대기 안내, 서버 증설). 배포하게 되면 다시 설계한다(지금은 로컬 전용, ADR 0002).
