# 0001. 결정을 ADR로 기록한다

- 상태: 채택
- 날짜: 2026-10-26

## 배경

PR #1–#40을 진행하면서 "배포하지 않는다", "API 필드는 추가만 한다", "PostgreSQL로 전환한다" 같은 결정을 대화로 내렸다. 결정의 이유가 대화와 PR 본문에 흩어져 있어서, 나중에 보거나 다른 사람이 보면 왜 그렇게 했는지 알기 어렵다.

## 결정

되돌리기 어렵거나 여러 곳에 영향을 주는 결정은 `docs/adr/`에 파일 하나로 기록한다. 기록 대상은 DB와 저장 방식, 외부 서비스, API 호환성, 코드 구조 원칙, 배포 방식이다. 작업 방식(브랜치, PR, 테스트)은 [CONTRIBUTING.md](../../CONTRIBUTING.md)에 둔다.

## 검토한 다른 안

- **CHANGELOG에 함께 적기:** CHANGELOG는 "무엇이 바뀌었나"를 날짜순으로 적는 곳이라, "왜 이 방법을 골랐고 무엇을 포기했나"가 묻힌다.
- **PR 본문에만 남기기:** 결정 하나가 여러 PR에 걸치면 찾기 어렵고, 결정을 바꿀 때 예전 결정과 연결할 수 없다.

## 결과

- 좋아지는 점: 결정 이유를 한 곳에서 찾을 수 있다. 면접에서 "왜 이렇게 했나요?"에 근거로 답할 수 있다.
- 감수하는 점: 큰 결정마다 문서를 하나 더 써야 한다.
