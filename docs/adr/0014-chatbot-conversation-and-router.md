# 0014. 챗봇은 대화를 서버에만 기억하고, 메시지 종류는 Jev로 판단한다

- 상태: 채택
- 날짜: 2026-10-28

## 배경

학생 챗봇(ADR 0011)은 질문을 하나씩 따로 처리했다. 그래서 "다시 말해줘", "요약해줘", "고마워" 같은 말도 새 질문으로 검색했고, 근거를 못 찾아 "답을 찾지 못했어요"를 돌려줬다. 챗봇이라면 이런 말에도 답해야 한다.

필요한 것은 두 가지다.
- 앞 대화 기억
- 메시지 종류 판단: 인사·감사(smalltalk) / 앞 답 다시·요약·쉽게(meta) / 앞 대화에 기대는 질문(followup) / 새 질문(new)

## 결정

### 1. 대화 기억은 서버 캐시에만 둔다 (`knowledge/conversation.py`)

- 사용자·대화별로 **최근 3턴, 마지막 메시지 뒤 30분** 동안 기억한다.
- 기억하는 것: 개인정보를 가린 질문, 보여 준 답, 상태, 근거 key.
- DB에는 남기지 않는다. 익명 대화 기록(ADR 0012)은 그대로다.
- 브라우저·앱이 보낸 "앞 대화"는 받지 않는다. 받으면 아무 글이나 "앞 답"이라며 넣고 "요약해줘"로 근거 없는 말을 하게 만들 수 있다.
- 클라이언트는 대화 번호(`conversation_id`)만 보낸다. 캐시 키에 사용자 id가 들어 있어, 남의 대화 번호를 보내도 이어지지 않는다.
- 웹 화면에 "새 대화" 버튼을 둔다. 앱 API 응답에는 `conversation_id`, `kind`를 추가한다(필드 추가만, ADR 0003).
- 캐시는 Django 기본(프로세스 메모리)이다. 서버 프로세스가 여럿이면 Redis 같은 공용 캐시가 필요하다(지금은 로컬 전용, ADR 0002).

### 2. 메시지 종류는 TypeSafe의 판단 전용 모델 Jev로 판단한다 (`knowledge/router.py`)

Jev는 문장을 쓰지 않고 "보기 중 하나 고르기" 같은 판단만 돌려주는 모델이다. `choice` 질문 하나로 네 종류 중 하나를 고르게 한다. 측정 결과 아래와 같이 정했다.

| 판단 방식 | tuned 39개 | held_out 25개 | 시간(중앙값) |
|---|---|---|---|
| 규칙(정규식) | 0.95 | **0.44** | 0ms |
| 로컬 exaone (답변 모델) | 0.87 | 0.88 / 0.92 | 80ms |
| 로컬 qwen3 | 0.87 | — | 80ms (단, 모델 교체 시 1.97초) |
| **Jev (기준 설명 한국어, 채택)** | **1.00** | **1.00** | 200ms |
| Jev (기준 설명 영어) | 1.00 | 0.96 | 200ms |

- 평가 문장: `knowledge/eval/router_messages.yaml`. 측정 명령: `python manage.py evaluate_router --backend jev|llm`.
- **tuned:** 규칙을 만들며 본 문장. **held_out:** 규칙을 보지 않고 새로 쓴 문장.
- 규칙은 tuned에서 0.95였지만 처음 보는 표현("땡큐", "뭐라고?", "핵심만", "주말엔 달라?")에서 0.44로 무너졌다. 테스트 문장에 과적합된 것이다.
- qwen3는 GPU(8GB)에 답변 모델 exaone과 함께 올라가지 못한다. 판단할 때마다 모델을 바꿔 올려야 해서, 로컬에서 판단한다면 exaone이어야 한다.
- 비용: 판단 한 번에 입력 약 500토큰, 100만 토큰당 0.042달러. 64문장 두 번 측정에 약 0.003달러였다.

**실패 대비:** Jev가 실패하면(키 없음, 장애, 3초 시간 초과) 로컬 exaone 판단기로 바꾼다. 그것도 실패하면 새 질문으로 처리한다. 판단이 틀려도 최악의 경우 처리 경로가 바뀔 뿐이고, 답은 인용 검사를 거친다.

### 3. 종류별 처리

| 종류 | 처리 |
|---|---|
| smalltalk | 정해진 짧은 답 (검색·답변 모델을 부르지 않음, 0.2초) |
| meta | 앞 답과 그 **근거 원문**을 함께 주고 요청대로 다시 쓰게 한다. 인용·첫 문장 검사를 똑같이 거친다. 앞 답이 없거나 "답을 찾지 못함"이었으면 다시 말할 것이 없다고 안내한다 |
| followup | 완전한 질문으로 다시 써서 새 질문처럼 답한다 (ADR 0016) |
| new | 지금과 같다 (`chat.answer_question`) |

## 데이터 전송에 관한 결정 (원칙 변경)

ADR 0007에서 "문의 내용이 PC 밖으로 나가지 않는다"를 장점으로 삼았다. Jev를 쓰면 **판단할 때마다 아래 내용이 TypeSafe 서버(외부)로 간다.**
- 학생의 마지막 메시지 (개인정보 가림)
- 바로 앞 한 턴의 질문과 답 (개인정보 가림)

이 범위로 사용자가 승인했다(2026-10-28). 답을 만드는 일과 근거 검색은 여전히 PC 안에서 한다.
- API 키는 환경변수 `TYPESAFE_API_KEY`로만 읽고 저장소에 넣지 않는다.
- 키가 없으면 자동으로 로컬 판단기를 쓴다.
- 외부 전송을 끄려면 `KNOWLEDGE_ROUTER_BACKEND=llm`으로 둔다.

## 측정: 다시 말하기·요약

`python manage.py evaluate_answer_drafts --mode meta`로 쟀다. facts가 있는 질문에 먼저 답하고, 그 답을 "요약해줘 / 다시 말해줘 / 더 쉽게 설명해줘"로 번갈아 다시 쓰게 했다. exaone, 두 번 쟀고 원문은 `knowledge/eval/results/2026-10-28-meta-*.json`에 있다.

| | 1회차 | 2회차 |
|---|---|---|
| 다시 쓴 답 표시 | 27/27 | 27/27 |
| 사실 유지 (첫 답에 사실이 있던 것 중) | 23/25 | 22/23 |
| 원문에 없는 숫자가 나온 답 | 1 | 0 |

- **새 숫자 검사:** 원문(첫 답 + 근거)에 없는 숫자가 다시 쓴 답에 나오면 지어낸 것으로 본다. 22:00 → "오후 10시"처럼 시각 표기만 바뀐 것은 같은 숫자로 본다.
- **새 숫자 1건:** "첫차 8시 25분"을 요약하며 "8시 33분에 학교 앞 도착"을 스스로 계산해 덧붙였다.
- **사실 미유지:** 대부분 바꿔 말한 경우다("변상" → "비용 부담", "동물 사육" → "고양이를 키우는 것").

## 실제 대화 확인 (Jev + exaone)

안녕(0.2초) → 통금 질문(첫 질문, 모델 로딩 포함 10.8초) → 요약해줘(2.3초) → 좀 더 쉽게 말해줄래?(2.7초) → 고마워(0.2초) → 도서관 질문(3.4초) → 다시 말해줘(3.7초). 종류 판단은 7개 모두 맞았다.

**발견한 한계:** "도서관 몇 시까지 해?"에 생활관 출입시간을 도서관 운영 시간처럼 답했다. 첫 문장이 "자료에 없다"고 하지 않아 기존 검사(ADR 0011)를 통과했고, 이어진 "다시 말해줘"가 그 답을 되풀이했다. 이는 새 질문 답변 경로의 한계이므로, **답을 보여 주기 전에 판단 모델로 "이 답이 근거로 뒷받침되는가"를 검사하는 방안**을 다음 설계로 검토한다.
