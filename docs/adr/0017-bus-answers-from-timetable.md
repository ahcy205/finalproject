# 0017. 셔틀 질문은 시간표에서 직접 계산해 답한다

- 상태: 채택
- 날짜: 2026-10-27

## 배경

챗봇 평가(ADR 0015, 2회)에서 셔틀 질문 3개는 6번 중 1번만 맞는 답이 보였다. 나머지는 Jev 검증이 숨겼는데, 대부분 방향을 반대로 읽은 답이었다.

- "터미널에서 학교 가는 첫차" → 시각(08:25)은 맞게 쓰고 "학교에서 터미널로 가는 첫차"라고 답함
- "학교에서 천안아산역 가는 셔틀" → 학교로 **오는** 편 시각(08:30…)을 나열함
- "두정역에서 학교 오는 버스" → 아산역 노선을 고름

시간표를 정리하다가 자료 오류도 찾았다. 아산역 노선의 학교 출발편이 `학교 출발 09:00 → … 탕정역 09:45 → 천안 아산역 09:30`처럼 앞 정류장보다 늦게 도착하는 것으로 적혀 있었다(11편 모두).

## 결정

1. **질문에서 정류장 하나와 방향이 분명하면 모델을 쓰지 않는다** (`knowledge/bus_answer.py`). `bus.yaml`에서 그 정류장의 시각을 골라 정해진 문장으로 답한다. 예: "두정역에서 학교로 오는 셔틀은 두정역 08:35 출발(학교 도착 09:10), … 에 있어요 [1]." 근거 [1]은 그 노선·방향의 버스 청크이고, 모델 문장이 없으므로 Jev 검증은 하지 않는다.
   - 방향 판단: "학교에서/학교 출발" → 나가는 편, "○○에서", "학교로/학교 가는/오는" → 오는 편, "○○ 가는/○○로" → 나가는 편
   - "첫차/막차"면 한 편만, 아니면 운행하는 편을 모두 보여 준다
   - 정류장의 다른 이름(터미널, KTX역 등)은 `bus.yaml`의 `stop_aliases`에 둔다
2. **애매하면 지금처럼 모델이 답한다.** 버스 관련 단어가 없음, 정류장이 없음 또는 둘 이상, 두 노선이 함께 서는 정류장(학교 앞 삼거리), 방향을 알 수 없음, 버스 청크가 검색 자료에 없음.
3. **버스 청크 제목과 첫 줄에 출발 → 도착을 적는다.** 모델로 넘어가는 질문을 위해서다. `천안 터미널 방면 학교로 오는 편` → `셔틀버스 천안 터미널 → 학교 (학교로 오는 편)`, 첫 줄은 `천안 터미널에서 학교로 오는 셔틀. 첫차 … 출발, 막차 … 출발.`
4. **아산역 학교 출발편 시각을 순서가 맞게 고쳤다**: 학교 앞 삼거리 :02, 동산2 교차로 :10, 탕정역 :20, 천안 아산역 :30(그대로). 실제 시간표가 아니라 기존 출발·도착 시각에 맞춘 값이다. 시각이 순서대로인지 테스트로 검사한다.

## 측정

챗봇 평가를 2회 돌렸다(exaone3.5:7.8b, Jev 검증). 셔틀 질문은 기존 3개에, 계산 방식을 만든 뒤 쓴 새 질문 6개("천안터미널 가는 셔틀 마지막 차", "KTX 타러 가야 하는데 학교에서 몇 시에 버스 있어?" 등)를 더했다. 새 질문을 넣은 이유는 기존 3개에만 맞춘 결과가 아닌지 보기 위해서다.

| | 수정 전 (10-28) | 제목만 수정 | 시간표 계산 |
|---|---|---|---|
| 셔틀 질문 맞게 표시 | 0/3, 1/3 | 1/3, 1/3 | **9/9, 9/9** |
| 셔틀 외 사실 포함 | 22/26, 21/26 | — | 22/26, 23/26 |
| 범위 밖 거절 | 1.00, 1.00 | 1.00, 1.00 | 1.00, 1.00 |
| 전체 사실 정확도 | 0.76, 0.76 | 0.90, 0.76 | 0.89, 0.91 |
| 숨긴 답 | 5, 7 | 4, 6 | 2, 3 |

- 제목만 고쳐서는 부족했다. 방향을 반대로 말하거나 다른 노선을 고르는 일이 계속됐다.
- 검색 평가(같은 38문항, 수정 전 → 후): hybrid hit@1 0.63 → 0.63, hit@5 1.00 → 1.00, MRR 0.792 → 0.792. vector hit@5 0.95 → 0.97.

## 검토한 다른 안

- **청크 문구만 더 다듬기:** 1차에서 6번 중 2번만 맞았다. 표를 읽는 일은 이 크기의 모델에 맞지 않는다고 봤다.
- **모델에게 정류장·방향만 뽑게 하고 시각은 코드로 계산:** 표현이 다양할 때는 더 낫지만, 0.4초 이상 늘고 모델 오류가 다시 들어온다. 정류장 이름이 10개 남짓이라 규칙으로 충분했다.
- **애매한 질문에 노선 두 개를 모두 보여 주기:** 질문과 관계없는 시각이 섞여 오히려 헷갈린다. 모델에게 넘긴다.

## 결과

- 좋아지는 점: 셔틀 질문의 시각과 방향이 항상 시간표와 같다. 모델과 Jev를 부르지 않아 바로 답한다.
- 감수하는 점: 규칙에 없는 표현("집 가는 버스", 정류장 없이 "막차 몇 시")은 여전히 모델이 답한다. 질문 하나에 셔틀과 다른 질문이 섞이면 셔틀 부분만 답한다. 정류장 이름이 바뀌거나 추가되면 `stop_aliases`도 고쳐야 한다.
- 다시 볼 조건: `export_chat_misses`에서 셔틀 질문이 모델로 넘어가 틀리는 표현이 자주 보이면 규칙이나 별칭을 늘린다.
