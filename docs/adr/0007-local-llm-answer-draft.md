# 0007. 문의 답변 초안은 로컬 LLM(Ollama)으로 만들고, 근거가 약하면 모델을 부르지 않는다

- 상태: 채택
- 날짜: 2026-10-26

## 배경

RAG 3단계에서는 관리자가 학생 문의에 답할 때 참고할 **답변 초안**을 만든다. 2단계에서 만든 검색(ADR 0006)이 근거를 찾고, 언어 모델(LLM)이 그 근거로 문장을 쓴다.

제약은 다음과 같다.

- **비용:** 유료 API(Claude, GPT)는 쓰지 않기로 했다. 포트폴리오 프로젝트이고 배포하지 않기 때문이다(ADR 0002).
- **개인정보:** 문의에는 학생 이름, 학번, 연락처가 들어갈 수 있다. 가능하면 데이터가 PC 밖으로 나가지 않아야 한다.
- **하드웨어:** 노트북 GPU RTX 4060(VRAM 8GB)과 RAM 16GB. 7–8B 모델을 4비트로 줄인 크기(약 5GB)까지 GPU에 올릴 수 있다.
- **지어내기(환각):** 기숙사 규정에 없는 시간이나 벌점을 지어내면 안 된다.

## 결정

1. **모델 실행:** 이 PC에서 [Ollama](https://ollama.com)로 실행하고 `http://127.0.0.1:11434/api/chat`을 부른다(`knowledge/llm.py`). 설정은 `settings.KNOWLEDGE_LLM`이고 환경변수 `KNOWLEDGE_LLM_BACKEND`, `KNOWLEDGE_LLM_MODEL`, `OLLAMA_HOST`로 바꾼다.
2. **기본 모델:** 일단 `exaone3.5:7.8b`로 둔다. 후보 세 개를 측정해 고르는 일은 다음 PR에서 하고, 결과를 새 ADR로 남긴다.

   | 후보 | 크기 | 만든 곳 | 비고 |
   |---|---|---|---|
   | exaone3.5:7.8b | 4.8GB | LG AI연구원 | 한국어 학습 비중이 큼. **비상업 라이선스** (포트폴리오·학습 용도라 사용 가능, 상업 서비스에는 쓸 수 없음) |
   | qwen3:8b | 5.2GB | Alibaba | Apache 2.0. 추론 모드가 있어 `think: false`로 끈다 |
   | gemma4:e2b | 4.6GB | Google | 작고 빠름. 한국어 품질은 측정으로 확인 |

3. **테스트·CI용 모델 대역:** `FakeLLM`은 받은 근거 중 첫 번째를 정해진 형식으로 인용해 항상 같은 답을 돌려준다. CI에는 GPU와 모델이 없다. 그래서 글솜씨가 아니라 **우리 코드**를 검사한다: 근거 부족 판단, 개인정보 가리기, 인용 번호 검사, 오류 처리.
4. **지어내기를 막는 두 겹 방어** (`knowledge/answering.py`)
   - **첫째 겹, 모델을 부르기 전:** 가장 가까운 근거의 유사도가 `MIN_SIMILARITY = 0.45`보다 낮으면 초안을 만들지 않고 "직접 답변해 주세요"로 돌려준다.
   - **둘째 겹, 모델 지시와 검사:** 지시문이 "근거에 적힌 내용만 쓰고, 문장마다 [번호]로 인용하고, 답할 수 없으면 '근거 자료에서 확인할 수 없습니다'라고 쓸 것"을 요구한다. 받은 초안의 [번호]가 실제로 넘긴 근거인지 검사해서, 없는 번호를 인용했거나 인용이 하나도 없으면 경고를 붙인다.
5. **개인정보:** 문의 제목·내용을 가린 뒤 검색과 모델에 넘긴다. 모델이 쓴 초안도 한 번 더 가린다. 같은 문의가 이미 검색 자료에 들어 있으면(답변된 문의) 그 문의는 근거에서 뺀다.
6. **사람이 확인:** 초안은 관리자 화면에 미리 채워 보여 줄 뿐 학생에게 자동으로 보내지 않는다(화면은 다음 PR).

## 근거 부족 기준값 측정 (bge-m3)

평가 질문 32개(답할 수 있는 질문)와 기숙사 자료로 답할 수 없는 질문 10개(`knowledge/eval/questions.yaml`의 `out_of_scope`: 도서관, 수강신청, 날씨 등)에서, 가장 가까운 근거의 코사인 유사도를 쟀다.

| 질문 묶음 | 개수 | 최소 | 중앙값 | 최대 |
|---|---|---|---|---|
| 답할 수 있는 질문 | 32 | 0.479 | 0.595 | 0.798 |
| 답할 수 없는 질문 | 10 | 0.406 | 0.487 | 0.567 |

| 기준값 | 답할 수 있는 질문 중 통과 | 답할 수 없는 질문 중 걸러짐 |
|---|---|---|
| **0.45 (채택)** | **32 / 32** | 4 / 10 |

두 묶음의 유사도 범위가 겹친다. 답할 수 없는 질문도 "학교", "신청", "기간" 같은 말 때문에 기숙사 자료와 어느 정도 가깝게 나오기 때문이다. 기준값을 더 올리면 답할 수 있는 질문까지 막는다. 그래서 기준값은 **답할 수 있는 질문을 하나도 막지 않는 선**으로 정했다. 나머지 6개는 둘째 겹(모델의 "확인할 수 없습니다" 답변)이 맡는다. 둘째 겹이 실제로 막는지는 모델 비교 때 함께 측정한다.

이 값은 bge-m3의 유사도 눈금에 맞춘 것이다. 다른 임베딩 모델(가짜 임베딩 포함)에서는 `min_similarity` 인자로 따로 준다.

## 검토한 다른 안

- **Claude·GPT API:** 문장 품질은 가장 좋을 가능성이 크다. 그러나 사용량만큼 비용이 들고 API 키를 관리해야 하며, 문의 내용이 외부로 나간다. `LLM` 클래스를 상속해 나중에 추가할 수 있게만 해 둔다.
- **llama.cpp·vLLM을 직접 실행:** 설정할 수 있는 것이 많지만, Windows에서 설치와 모델 관리가 번거롭다. Ollama는 설치 한 번과 `ollama pull`로 끝나고 HTTP API가 같다.
- **Hugging Face transformers로 파이썬 안에서 실행:** 웹 서버 프로세스가 모델(수 GB)을 직접 메모리에 올려야 한다. 별도 프로세스(Ollama)로 두면 웹 서버는 가볍게 유지된다.
- **기준값 없이 모델 지시만 쓰기:** 작은 로컬 모델은 지시를 어기고 그럴듯하게 지어낼 수 있다. 확실히 관련 없는 질문은 모델을 부르기 전에 거르는 편이 안전하고 빠르다.

## 결과

- 비용 없이, 데이터를 PC 밖으로 보내지 않고 초안을 만든다.
- 감수하는 점
  - Ollama가 켜져 있어야 한다. 꺼져 있으면 오류를 보여 주고 관리자가 직접 답한다.
  - 초안 한 건에 수 초에서 수십 초가 걸린다(GPU 기준, 모델 비교 때 측정).
  - 7–8B 모델은 큰 API 모델보다 문장이 어색하거나 지시를 덜 지킬 수 있다. 그래서 인용 검사와 사람의 확인을 둔다.
- 다시 볼 조건
  - 모델 비교 결과 세 후보 모두 인용·거절 기준을 못 넘으면 API 모델을 다시 검토한다.
  - 실제 문의가 쌓이면 답할 수 없는 질문 묶음을 늘려 기준값을 다시 잰다.
