# 0003. 앱 API는 하위 호환을 지킨다

- 상태: 채택
- 날짜: 2026-10-26

## 배경

`/api/`는 별도 저장소에 있는 Android 앱(Kotlin)이 쓴다. 서버만 고치고 앱은 바로 고칠 수 없는 경우가 많아서, 응답 형식이 바뀌면 이미 설치된 앱이 깨진다.

## 결정

- 응답에는 필드를 **추가만** 하고, 기존 필드의 이름·타입·의미를 바꾸거나 지우지 않는다. 예: PR #25에서 외박 `status`, 공지 `image` 추가
- 동작을 바꾸는 기능은 **선택형**으로 넣는다. 예: PR #34에서 `?page=`를 줄 때만 페이지 나누기, 주지 않으면 기존처럼 전체 반환
- 새 엔드포인트는 자유롭게 추가할 수 있다. 예: PR #35 `POST /api/logout/`
- API를 바꾸면 `dorm/schema.py`의 문서 설명도 같은 PR에서 고친다. CI가 문서 경고를 실패로 처리한다.

## 검토한 다른 안

- **API 버전 나누기(`/api/v2/`):** 엔드포인트 19개 규모에서는 두 버전을 함께 유지하는 비용이 더 크다.
- **앱과 동시에 바꾸기:** 앱 저장소가 여기 없어서 동시 배포를 보장할 수 없다.

## 결과

- 좋아지는 점: 앱이 서버 변경과 상관없이 계속 동작한다.
- 감수하는 점: 잘못 지은 필드 이름도 그대로 남는다. 응답에 쓰지 않는 필드가 쌓일 수 있다.
- 예외: 보안 문제로 데이터를 숨겨야 할 때(예: PR #9 문의 열람 권한)는 호환보다 보안을 우선한다.
