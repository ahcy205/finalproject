# 0016. 이어지는 질문은 완전한 질문으로 다시 써서 답한다

- 상태: 채택
- 날짜: 2026-10-28

## 배경

메시지 종류 판단(ADR 0014)이 "그럼 호실 점검은?", "막차는?" 같은 이어지는 질문(followup)을 골라내지만, 지금까지는 새 질문처럼 그대로 검색했다. 생략된 말("셔틀", "세탁기")이 없어 엉뚱한 근거를 찾거나 근거 부족으로 막혔다.

## 결정

followup이면 앞 대화를 보고 혼자서도 뜻이 통하는 질문 한 줄로 다시 쓴 뒤, 새 질문과 똑같은 길(검색 → 답 → 인용·첫 문장 검사 → Jev 검증)로 답한다 (`conversation.rewrite_followup`).

- **모델:** 답을 쓰는 로컬 모델(exaone)을 그대로 쓴다. Jev는 글을 쓰지 못하고, 다른 모델을 올리면 GPU에서 바꿔 끼워야 해 더 느리다.
- **입력:** 서버 캐시의 최근 3턴(개인정보 가림). 앞 질문(다시 쓴 질문이 있으면 그것)과 앞 답 앞 200자. 인사는 뺀다. 프롬프트에 예시 3개.
- **검증:** Jev 검증과 검색은 다시 쓴 질문으로 한다. 학생 화면의 질문은 원래 메시지 그대로다.
- **실패 처리:** 모델 오류, 빈 출력, "확인할 수 없습니다", 물음표로 끝나지 않는 출력이면 다시 쓰기 실패로 보고 원래 메시지로 답한다.
- **기록:** 다시 쓴 질문은 대화 기억(다음 이어지는 질문이 볼 수 있게)과 익명 기록 `ChatLog.rewritten_question`(👎·못 답한 질문 분석용)에 남긴다. API 응답은 바꾸지 않는다.

## 확인

`python manage.py evaluate_answer_drafts --mode followup` — `knowledge/eval/followup_dialogues.yaml` 15개 대화. 앞 질문에 실제로 답한 뒤 이어지는 질문을 다시 쓰고, 검색 상위 5개에 정답 청크가 있는지 원래 메시지와 비교한다. exaone3.5:7.8b + bge-m3 + Jev, 물음표 검사를 넣은 뒤 2회.

| | 1회 | 2회 |
|---|---|---|
| 검색 적중 (원래 메시지) | 0.87 | 0.87 |
| 검색 적중 (다시 쓴 질문) | 0.93 | 1.00 |
| 다시 쓰기 실패 → 원래 메시지 | 2 | 1 |
| 답 표시 | 12/15 | 13/15 |
| 사실 포함 | 10/15 | 10/15 |
| 다시 쓰기 시간 중앙값 | 0.4초 | 0.4초 |

- 목표(다시 쓴 질문 검색 적중 ≥ 0.9)를 넘었다. 늘어나는 시간은 이어지는 질문에만 약 0.4초.
- 물음표 검사 전에는 15개 중 1~2개에서 질문 대신 앞 답을 보고 답을 써 버렸다("세탁기 마지막 시간은 오전 7시까지입니다."). 그 문장으로 검색·검증하면 틀린 답이 근거처럼 보이므로 막았다.
- 사실이 빠진 답은 대부분 다시 쓰기가 아니라 답 쪽 문제다(셔틀 시간을 잘못 읽음, "관계 부서"를 다른 말로 씀, Jev가 숨김). 새 질문에서도 같은 문제가 있다.
- 남은 다시 쓰기 오류: "전기장판 써도 돼? → 고양이는?"을 "반려동물 동반 시 전기장판 사용 규정"처럼 앞 주제와 섞는 경우가 있다.

## 고르지 않은 안

- **앞 질문과 메시지를 이어 붙여 검색:** 모델 호출이 없어 빠르지만, 앞 주제 단어가 섞여 "고양이는?"에 전기장판 근거가 먼저 나온다. 답 모델과 Jev도 어떤 질문에 답하는지 알 수 없다.
- **Jev로 다시 쓰기:** Jev는 판단(예/아니요 확률)만 하고 글을 쓰지 못한다.

## 결과

- 이어지는 질문이 새 질문과 같은 검사를 거친다. 다시 쓰기가 틀려도 Jev가 다시 쓴 질문 기준으로 검증하므로, 엉뚱한 답이 보일 위험은 새 질문과 같다.
- 다시 쓰기 실패 시 원래 메시지로 답하므로, 생략이 심한 메시지("몇 시까지 써도 돼?")는 예전처럼 엉뚱한 근거를 찾을 수 있다.
- 실제 기록이 쌓이면 `rewritten_question`이 있는 👎를 모아 평가 대화에 추가한다.
