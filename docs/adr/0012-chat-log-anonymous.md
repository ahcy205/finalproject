# 0012. 챗봇 대화 기록은 익명으로 180일 보관하고, 못 답한 질문으로 자료를 보강한다

- 상태: 채택
- 날짜: 2026-10-28

## 배경

학생 챗봇(ADR 0011)은 사내·학교 FAQ형으로 설계했다. 이 유형의 핵심은 **못 답한 질문을 찾아 자료를 보강하는 순환**이다. 그러려면 어떤 질문에 답하지 못했는지, 어떤 답이 도움이 안 됐는지 남아 있어야 한다.

반면 기숙사 문의에는 이름·학번·연락처나 개인 사정이 섞일 수 있다. 챗봇 대화 기록을 다루는 방식은 보통 세 가지다.

| 유형 | 기록 방식 |
|---|---|
| 개인 비서형 (ChatGPT 등) | 계정에 연결해 저장 (지난 대화 보기 기능), 삭제 기능·보관 기간 |
| 고객센터·기관 안내형 | 품질·분쟁 대응을 위해 저장, 개인정보처리방침에 목적·기간 명시 |
| 사내·학교 FAQ형 | 익명 기록과 👍/👎만 모아 못 답한 질문을 찾음 |

## 결정

FAQ형에 맞춰 **익명 기록 + 👍/👎**로 한다 (`knowledge.models.ChatLog`, `knowledge/chat_log.py`).

| 저장함 | 저장하지 않음 |
|---|---|
| 질문 (개인정보를 가린 뒤, 500자까지) | 누가 물었는지 (사용자와 연결하지 않음) |
| 답 상태, 보여 준 답, 모델이 쓴 원래 답 (숨긴 답 포함, 개인정보 가림) | IP, 브라우저 정보 |
| 근거 key, 인용한 key, 유사도, 모델, 걸린 시간, 웹/앱 구분 | 평가 키 원문 (해시만 저장) |
| 👍/👎, 👎 이유 (틀림 / 질문과 관계없음 / 부족함) | |

- **평가는 답을 받은 사람만, 한 번:** 답과 함께 일회용 키(`feedback_token`)를 준다. DB에는 그 키의 SHA-256 해시만 저장한다. 사용자와 연결하지 않아도 남의 답을 평가하는 일을 막을 수 있다.
- **보관 기간 180일:** `python manage.py purge_chat_logs`가 지난 기록을 지운다. 한 학기 동안 모은 질문으로 다음 학기 전에 자료를 보강할 수 있는 길이다.
- **안내:** 챗봇 화면과 API 문서에 저장 내용, 목적, 보관 기간을 적고 "이름·학번·연락처는 입력하지 마세요"라고 안내한다.
- **기록 실패가 답을 막지 않는다:** 저장 중 오류가 나면 로그만 남기고 답은 그대로 준다(`log_id`가 null).
- **관리자:** Django 관리자 화면에서 읽기 전용으로 본다. 상태, 평가, 이유, 웹/앱으로 거르고 질문·답으로 검색한다. 추가·수정·삭제는 막았다(삭제는 보관 기간 명령으로만).

## 개선 순환

```
못 답함 / 숨긴 답 / 👎  →  python manage.py export_chat_misses (평가 질문 형식 YAML, 같은 질문은 횟수로 묶음)
→ 관리자가 원인 확인: 자료 없음 → 공지·규정 보강 / 말이 다름 → synonyms.yaml / 틀린 답 → 평가 질문에 추가
→ python manage.py evaluate_answer_drafts --mode chat 으로 다시 측정
```

## 검토한 다른 안

- **사용자와 연결해 저장:** 학생별 지원에는 쓸 수 있지만, 이 기능의 목적(자료 보강)에는 필요 없고 개인정보 부담이 커진다.
- **기록하지 않음:** 개인정보 부담은 없지만, 어떤 질문을 놓치는지 알 수 없어 FAQ형 챗봇의 개선 순환을 만들 수 없다.
- **브라우저 세션에 평가 키 보관:** 앱(API)에서는 쓸 수 없어서, 답과 함께 키를 돌려주는 방식으로 통일했다.

## 한계

- 개인정보 가리기는 전화번호·이메일·학번 모양과 질문한 사람의 이름·아이디만 가린다. 다른 사람의 이름이나 자유롭게 쓴 개인 사정은 남을 수 있어서, 입력하지 말라는 안내로 보완한다.
- 기록 삭제는 명령을 실행해야 일어난다. 배포한다면 매일 자동으로 실행되게 해야 한다(지금은 로컬 전용, ADR 0002).
