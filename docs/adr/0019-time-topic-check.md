# 0019. 답의 시각이 근거의 같은 주제 줄에 있는지 규칙으로 확인한다

- 상태: 채택
- 날짜: 2026-10-27

## 배경

규칙 제3조에는 "출입시간 06:00-23:00"과 "천정등 00:00-06:00 소등"이 함께 있다. 모델은 "방 불은 몇 시에 꺼야 돼?"에 가끔 "23:00 이후 소등"이라고 답했다. 근거에 있는 시각을 다른 주제에 붙인 답이라, Jev 검증(ADR 0015)도 통과해 학생에게 보인 적이 있다(ADR 0018). 근거에 질문과 가까운 줄을 표시해 모델이 덜 헷갈리게 하는 방법은 측정에서 나빠져 기각했다(ADR 0018).

## 결정

모델을 쓰지 않는 검사를 둔다 (`knowledge/time_check.py`).

1. 답을 문장으로 나누고 시각을 찾는다. "23:00", "밤 11시", "오후 5시 30분", "7시 반", "자정", "24시"를 같은 형식으로 바꾼다. 오전·오후가 없는 "11시"는 11:00과 23:00을 모두 인정한다.
2. 시각마다 그 시각이 적힌 근거 줄(또는 근거 제목)을 찾는다.
   - 없으면 **근거에 없는 시각**
   - 있지만 문장과 겹치는 주제어가 없으면 **다른 주제의 시각**. 주제어는 한글 두 글자 앞부분으로 비교하고, 흔한 말(생활관, 시간, 까지 등)은 뺀다. `synonyms.yaml`도 더한다(통금 → 출입시간).
3. **챗봇**: Jev 검증 전에 검사한다. 걸리면 답을 숨기고(`unverified`) Jev는 부르지 않는다. 사유는 익명 기록의 검증 결과에 "근거와 다른 시각: …"으로 남는다. 다시 말하기·요약 답도 같은 경로를 거친다. 셔틀 시간표 답(ADR 0017)은 모델 문장이 없어 검사하지 않는다.
4. **관리자 답변 초안**: 숨기지 않고 "근거와 다른 시각이 있을 수 있습니다" 경고만 붙인다. 관리자가 확인하고 고쳐 보내는 용도이기 때문이다.

## 측정

**구현 전, 저장된 결과로 확인**: 챗봇 평가 결과 12개에서 학생에게 보인 답 339개에 규칙을 적용했다.

| | 통과 | 걸림 |
|---|---|---|
| 맞는 답 318 | 317 | 1 (셔틀, 지금은 시간표 답이라 해당 없음) |
| 틀린 답 21 | 16 | 5 ("23:00 소등" 4, 셔틀 시각 1) |

**구현 후 챗봇 평가 2회** (exaone3.5:7.8b, Jev). 기존은 `2026-10-27-chat-bus-table-1/2.json`, 이번은 `2026-10-27-chat-time-check-1/2.json`이다.

| | 기존 | 시각 검사 |
|---|---|---|
| 학생에게 보인 답 (답할 수 있는 38개 중) | 35 / 35 | 32 / 34 |
| 그중 틀린 답 | 2 / 0 | 0 / 0 |
| 시각 검사로 숨김 | – | 2 / 2 |
| 사실 정확도 | 0.89 / 0.91 | 0.89 / 0.89 |
| 잘못 거절 | 0.08 / 0.08 | 0.16 / 0.11 |

- 시각 검사로 숨긴 4개는 모두 틀린 답이었다: "23:00 이후 소등" 2회, 석식 배식 시간 "오후 7시 30분부터 9시"(근거에 없음), 신입생 질문에 덧붙인 "출입은 오전 6시부터 자정까지".
- 잘못 거절이 늘어난 질문(통금, 흡연, 지각 벌점)은 시각 검사를 통과한 뒤 **Jev가** 숨긴 것이다. Jev 경로는 바뀌지 않았으므로 실행마다 달라지는 차이로 본다. 계속 늘어나면 Jev 기준을 다시 본다.

## 감수하는 점

- 시각만 본다. "관계 부서" 대신 "관리 부서"처럼 시각이 아닌 오류(저장된 결과의 틀린 답 21개 중 16개)는 그대로다.
- 학생 말투가 근거와 너무 다르면("불 꺼야" vs "소등") 맞는 답도 숨겨질 수 있다. 모델은 대개 근거 용어를 쓰기 때문에 측정에서는 없었다. 생기면 익명 기록의 사유로 찾아 `synonyms.yaml`에 넣는다.

## 다시 볼 조건

- 익명 기록에서 "근거와 다른 시각"으로 숨긴 맞는 답이 보이면 주제어 비교를 손본다.
- 숫자(벌점, 금액)에도 같은 문제가 보이면 같은 방식으로 넓힌다.

## 숫자 점검이 필요한지 측정 (2026-11-01)

"다시 볼 조건"의 숫자 오류를 확인하려고 평가 질문에 숫자 질문 11개를 더했다(총 49개). 벌점표 항목 6개(3·4·5·7·10점이 섞여 항목과 점수를 바꿔 답하기 쉬움), 봉사 감면 2점, 퇴관 기한 2주, 입관 기한 7일, 실 이동 통지 7일, 2학년 배정 60%다. 챗봇 평가를 2회 돌렸다(`2026-11-01-chat-numbers-1/2.json`).

| | 1회 | 2회 |
|---|---|---|
| 사실 정확도 | 0.89 | 0.87 |
| 잘못 거절 | 0.08 | 0.12 |
| 숫자 질문 14개 중 학생에게 보인 답 | 13 | 13 |
| 그중 숫자가 틀린 답 | 0 | 0 |
| 보인 답 전체에서 자료 어디에도 없는 "N점·N원·N일·N주·N%" | 0 | 0 |

- 숫자를 틀리게 말한 답은 없었다. 그래서 숫자 점검은 만들지 않고, 추가한 질문은 회귀 검사로 남긴다.
- 숫자 질문에서 문제는 오히려 **잘못 거절**이었다. "외박 신청 안 하고 자고 오면 벌점 몇 점"(7점)은 2회 모두 숨겨졌다(근거 부족 1회, Jev 1회).
- 사실 정확도가 1이 아닌 것은 말을 바꾼 답("동물" 대신 "고양이")을 채점이 틀리다고 본 경우와 잘못 거절이다.
