돔고돔락 흐름도

웹 화면과 Android 앱이 하나의 Django 서버와 데이터베이스를 함께 씁니다. 요청이 어디로 들어가서 어떤 검사를 거치는지, 주요 업무 데이터가 어떻게 바뀌는지를 코드 기준으로 정리했습니다.

웹 브라우저 경로 Android 앱 경로 차단 · 주의
시스템 구조 요청 처리 순서 주요 업무 흐름 데이터 구조 페이지 권한 앱 API 알려진 문제

시스템 구조

요청은 모두 finalproject/urls.py에서 갈라집니다. /api/로 시작하면 dorm 앱의 REST API가 JSON으로 답하고, 나머지는 web 앱이 HTML 페이지로 답합니다. web 앱에는 자체 모델이 없고 dorm/models.py를 그대로 가져다 씁니다.

요청 처리 순서

웹 뷰에 붙은 데코레이터가 순서대로 요청을 걸러냅니다. 모든 뷰가 세 검사를 다 거치지는 않습니다. 예를 들어 외박 승인은 세 가지 모두, 게시글 상세는 로그인 검사만 거칩니다.

주요 업무 흐름

세 업무 모두 같은 모양입니다. 학생이 신청하면 기록이 생기고, 관리자가 그 기록을 바꾸면, 학생이 결과를 확인합니다.

데이터 구조

모든 모델은 dorm/models.py에 있습니다. 회원가입으로 User가 생기면 UserProfile이 자동으로 함께 만들어집니다.

페이지별 접근 권한

웹 화면 기준입니다. "로그인 필요"는 로그인 페이지로 이동한다는 뜻입니다.

앱 API

Android 앱은 /api/login/에서 받은 Token을 Authorization: Token <값> 헤더에 넣어 호출합니다. 응답은 모두 JSON이며 대부분 success 필드로 성공 여부를 알려 줍니다. 요청·응답 형식 전체는 /api/docs/(Swagger)에서 보고 바로 호출해 볼 수 있습니다.
